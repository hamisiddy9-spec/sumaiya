**1 — Fix the ATS-checker upload-limit mismatch · 0.5 day**
- **What:** `apps/web/app/[locale]/(marketing)/ats-checker/ats-checker-client.tsx:10` → `const MAX_BYTES = 15 * 1024 * 1024;` and it tells the user "max 15 MB" in both languages (line 68). The server refuses anything over 4 MB: `apps/web/lib/api/routes/tools.ts:15` → `const MAX_PDF_BYTES = 4 * 1024 * 1024; // 4 MB (under Vercel's ~4.5 MB body limit)` (both quoted verbatim, read today). Lower the client limit to 4 MB and say so, or raise it by routing the upload differently.
- **Why it matters:** a phone-scanned CV is routinely 5–15 MB. Today the UI promises acceptance and the server returns 413 — a guaranteed dead end on the free tool that is the front door.
- **Know it worked:** zero 413 responses from `/api/tools/extract-text` after the change, and the client error text matches the server cap exactly.

**2 — Set the AI provider key · 1 day**
- **What:** the Vercel variable exists but is empty, so every AI path answers 503. Set the key, or if the empty value is a cost decision, make it explicit and degrade the UI honestly instead of erroring.
- **Why it matters:** the assistant, cover letters, tailoring, CV import and interview prep are the product's loudest claims. Zety, Rezi, Novoresume, BrighterMonday KE and Careergo all lead with working AI; Sumaiya's is dark.
- **Know it worked:** a production smoke test returns 200 with generated content from `/api/ai/assistant-turn`, `/api/ai/cover-letter` and `/api/ai/tailor-cv`; the 503 rate on `/ai/*` drops to zero.

**3 — Strip "ATS" from Swahili copy and ban it in the tripwire · 1 day**
- **What:** rewrite the four Swahili strings in `apps/web/lib/i18n/translations.ts` (162, 169, 252, 254) to describe the outcome — the CV that gets seen, the CV that passes — then add `ATS` to the banned-pattern table in `lib/swahili-lint.test.ts` (and its native mirror) so it cannot come back.
- **Why it matters:** it is your own rule, broken in production, on the page a Tanzanian reads first. It also borrows credibility from Western ATS systems that most Tanzanian employers do not run.
- **Know it worked:** `grep -rn "ATS" apps/web/lib/i18n/translations.ts` returns nothing in the `sw` block, the lint test fails if the term is reintroduced, and the live Swahili homepage contains no "ATS".

**4 — Fix the native chat composer tap · 1 day**
- **What:** device QA (2026-09-11) recorded P0-2: tapping the composer did nothing (`mInputShown=false`, `mServedView=null`). Commits since (`293005c`, `0de6b68`) touched layout and accessibility labels, not focus. **State unknown — re-test first, then fix.**
- **Why it matters:** "Ask Sumaiya" is the app's advertised centrepiece; a chat you cannot type into is worse than no chat.
- **Know it worked:** a jest test that mounts the composer, fires a press, and asserts the handler runs — plus one screenshot from the next device pass.

**5 — Fix native email-OTP sign-in · 2 days · re-test before fixing**
- **What:** QA recorded email OTP dead on production. **Critical context I found:** that APK pointed at `EXPO_PUBLIC_API_URL=https://sumaiyaai.vercel.app` and Supabase project `ayczgaddnufdxnhizpcr` — both of which are **deleted** (`docs/HANDOFF-2026-09-20.md`). So the 2026-09-11 P0s describe a build wired to dead infrastructure and **must not be re-fixed blind**. `git log 890a5cd..HEAD | wc -l` → **259 commits** since that test, including `cbbf44f fix(native): OTP validation + version 1.6.18`.
- **Why it matters:** if OTP is still dead on the current build, everyone without a Google account is locked out of the app. Google sign-in worked in the only device test — that mitigant is the only reason this ranks below #9.
- **Know it worked:** a fresh install signs in with a real email address on the live backend and receives the code; the error string "Error sending magic link email" disappears from logs.

**6 — Cut the install payload · 2 days**
- **What (measured today, first-hand):** `apps/native/android/app/build/outputs/apk/release/app-release.apk` = **53,970,426 bytes (51.5 MiB)**; inside it, `classes*.dex` total **36.2 MB** and `lib/arm64-v8a/*.so` **28.2 MB**; `assets/index.android.bundle` 6.9 MB. `apps/native/android/app/build.gradle:104` defaults `enableMinifyInReleaseBuilds` to **false** and shrinkResources to false; `gradle.properties:42` sets `hermesEnabled=true`. So the release build is shipping **unminified** Java/Kotlin. Turn on R8 + resource shrinking, and ship an **AAB** (Play delivers per-device slices) instead of a universal APK.
- **Why it matters:** 52 MB is a meaningful purchase on a TZS-bundle data plan; the install itself is the first thing a Tanzanian user pays for, before any feature proves itself. (INFERENCE: no competitor payload was measured, so this is about your own waste, not a benchmark.)
- **Know it worked:** release size recorded before/after in the repo and asserted in CI (`scripts/test-release-invariants.js` already exists); target a material drop in the .aab download size for an arm64 device.

**7 — A Tanzanian persona in the previews · 1 day**
- **What:** the sample CVs users see are Kenyan. Homepage hero: "Amara Osei … Nairobi, Kenya … amaraosei.dev". Template gallery: "James Kariuki … University of Nairobi … Nairobi, Kenya" (OBSERVED — direct, https://sumaiya.app and https://sumaiya.app/sw/templates). Replace with Tanzanian names, Tanzanian employers and TZS salary figures, and keep one English-register and one Swahili-register variant.
- **Why it matters:** a Tanzanian user deciding whether this tool is *for them* sees a Nairobi software engineer with a personal website. That is a trust signal in the wrong direction, and it is pure content work.
- **Know it worked:** the sample data in `TEMPLATES` preview components has no "Nairobi"/"Kenya" strings outside deliberately Gulf/international examples.

**8 — The airplane-mode pass · 3 days (2 QA + fixes)**
- **What:** a written script — install fresh, turn off all radios, launch, browse templates, create a CV from scratch, save, export PDF, kill the app, reopen, confirm the CV survived — then fix what breaks. The inventory is explicit that on-device offline has **never** been tested; the web Playwright suite is not in CI and has never run in this tree.
- **Why it matters:** "works when the network doesn't" is the single structural claim no global competitor can match and no local one offers. An untested version of it is a liability discovered at the worst moment — when the user has no data left.
- **Know it worked:** the script is committed and passes; it becomes a required step before every release (it is one more step in the release runbook, not a CI job).

**9 — Native guest mode · 4 days · see §5**
- **What:** port `app/(app)/editor/cv/try` to native: a first-run user picks a template, fills the CV, exports the PDF, and *only then* meets the account ask — exactly what web already does, with the draft stashed locally and migrated on sign-in (web already has `lib/migrate-guest-failure.ts` and `app/(app)/migrate-guest/page.tsx` as reference).
- **Why it matters:** it is the product's own non-negotiable rule, and on native it is simply false. The web proves the design works; the APK is the product.
- **Know it worked:** a fresh install reaches an exported PDF with zero taps on "sign in"; track "% of first sessions reaching export without an account" as a first-class number.

**10 — Job-feed integrity · 3 days**
- **What:** delete `apps/web/app/api/jobs/feed/route.ts` (8 hardcoded jobs — Kilimanjaro Retail, Jangwani Telecom — and, verified today, **zero references anywhere in `apps/web`**), since the real feed is `/jobs` + `lib/api/routes/jobs.ts` with 14 adapters. Then make the silently-skipped key-gated adapters (Adzuna, Jooble, Careerjet, Talent, USAJobs) visible in admin instead of failing quietly, and light up the free ones.
- **Why it matters:** a jobseeker landing on `/jobs` cannot tell a thin feed from a rich one, and the difference decides whether they come back. SwiftKazi advertises 34+ boards scanned every 6 hours — that is the bar in this market.
- **Know it worked:** no code path resolves to the mock array; an admin view reports live vs skipped source counts per run, and the live-source count goes up over time.
- **Do not** scrape boards whose terms forbid it just to raise that count.

*Honourable mention (11th, ratio 1.5, ~2 days): triage the **219** unoffered registry templates — promote the good ones into the curated set or delete them — and stop adding new ones until that is done. The native suite currently renders all 218 in CI for templates no user is offered.*

# 4 · What not to do

Skip these deliberately. Each is a real competitor feature and the wrong move *here*.

1. **Interview copilots / live AI mock interviews** (Rezi, Jobscan). The current gap is that a stranger cannot get into the app; building a per-token premium feature on top of a broken front door is the over-engineering you keep rejecting. The existing native mock interview can stay as-is, uninvested in.
2. **Auto-apply at scale** (Jobscan Auto Apply, Jobright "Orion", and regionally **SwiftKazi at KES 60/application**). Two reasons: SwiftKazi already owns that niche at a price you cannot undercut, and bulk-applying into a small, reputation-sensitive local market risks the *user's* standing with an employer. Also much Tanzanian hiring runs through WhatsApp, email and walk-ins, which auto-apply cannot reach.
3. **LinkedIn optimisation** (Careerflow, Kickresume's importer). LinkedIn penetration among Tanzanian SME/informal jobseekers does not justify the build, and the research run's own gap analysis says the model "doesn't transfer to markets where LinkedIn penetration is low".
4. **Selling ATS scoring as the headline mechanism, in any language.** Jobscan's edge is knowing *named Western* ATS parsers (Workday, Greenhouse, Lever, Taleo) that most Tanzanian employers do not run. Keep the check as a quiet confidence signal ("your CV is ready to send"); never make the consumer product an ATS-audit tool. Use the term freely in *English* technical/admin surfaces — the rule is about the Swahili user-facing copy.
5. **Gulf compliance tooling right now.** Photo, nationality, visa status and notice-period fields are cheap to add, but degree attestation is a **4–8 week paper process** no software can complete. Build Gulf fields only when there is a real Gulf employer relationship to receive the output; otherwise it is polish on a funnel that cannot finish.
6. **Applicant-ranking gamification** ("you are #47 of 200", Fuzu). In a high-unemployment market it demoralises more than it motivates, and every rank change becomes a support ticket.
7. **Any dark-pattern billing** (Zety's $1.95→$25.95/4 weeks, Jobscan's 2-day, 3.5%-fee refund window, Simplify's no-refund policy, region-varying client-side prices). With this product's name on it, opacity in pricing is not a UX preference — it is a line you do not cross.
8. **Stop maintaining two things you already have:** the **219 unoffered templates** plus the native CI cost of rendering all 218 of them, and the **dead `/api/jobs/feed` mock** that duplicates the real feed and will eventually be mistaken for it.

---

# 5 · The one thing

**Ship native guest mode — and use one device pass on a current build as its acceptance test.**

**The evidence, in order of weight:**

1. **It is your own non-negotiable, and native violates it.** "A guest must be able to finish a CV and
   download it BEFORE being asked for an account." Web honours it (verified live today:
   `/editor/cv/try` → 200; the sign-up prompt fires *after* delivery). Native does not —
   `apps/native/src/navigation/root-navigator.tsx:245` gates everything behind `!user ? (`.
2. **The asymmetry with the runner-up (OTP, #5) is decisive.** In the only device test, **Google sign-in
   worked** — so a broken email OTP still leaves an entry path, which is why OTP ranks below guest mode.
   Guest mode has no mitigant: a user who will not create an account is not slowed down, they are stopped.
3. **The APK is the product, and its entry path has never been verified against live infrastructure.**
   The one device QA pass (2026-09-11, `QA-REPORT-2026-09-11.md`: verdict "**NOT SHIP-READY**") was against
   `sumaiyaai.vercel.app` and Supabase `ayczgaddnufdxnhizpcr` — both since deleted. `git log 890a5cd..HEAD`
   = **259 commits**. So two things are true at once: the last known P0s may be artefacts of a dead backend,
   and nobody currently knows whether the app a Tanzanian installs can be entered at all. That uncertainty
   is precisely why the first change of the week should *end* at an exported PDF on a real phone.
4. **It is the cheapest item with impact 10.** The web implementation is a working reference — including
   the draft-survives-sign-in path (`lib/migrate-guest-failure.ts`, `app/(app)/migrate-guest/page.tsx`) —
   so this is a port with a spec, not a design exercise. Four days.
5. **It is the precondition for everything else on the list.** Fixing AI, fixing OTP, testing offline,
   trimming templates — all assume a user got in. Nothing else on this list pays off until they can.

**Ship order for the week, if the week allows only one thing plus its proof:**
guest mode → then **one device pass on the current APK, against the live backend**, following item 8's
airplane-mode script. Then OTP (item 5, now re-tested rather than re-fixed blind) and the 0.5-day
ATS-checker fix (item 1), which costs half a day and removes a guaranteed rejection.

**What I would not trade for it:** the AI key (#2). It is one env var and it is the difference between
"an AI product" and "a 503" — but it upgrades a feature, not the door.
