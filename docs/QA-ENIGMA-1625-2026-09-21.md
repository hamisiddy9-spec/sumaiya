**Verdict: WORKS for the Google branch, BROKEN for the raw-English case.** Two distinct branches were

### 3.2 An unnamed failure leaks raw English SDK text onto a Swahili screen — BROKEN
I entered `qama-1625@example.com` and tapped `Nitumie msimbo`. On-screen banner
(`enigma/08-after-send.png`), quoted exactly:

field's inline validation error in Swahili (`Weka barua pepe sahihi`, `enigma/qa7.xml`) clears as soon

## 1 (cont.) THE CV PATH OFFLINE — the headline result

**Verdict: WORKS — the export completed end to end with the radios off, and wrote a real PDF.**

### 1.2 The offline window — what I ran and what I saw
I ran, in this order:
```
adb -s … shell svc wifi disable
adb -s … shell svc data disable
```
and confirmed the window was genuinely closed before doing anything else:
```

```
(Re-checked a second time immediately after the export completed — still `0` / `none`.)

Then, entirely offline, I tapped `Pakua PDF` in the CV editor.

**What I saw:** the app opened Android's Storage Access Framework folder picker —
`Files on Hisense Enigma`, with `CREATE NEW FOLDER` and `USE THIS FOLDER`
(`enigma/16-export-offline.png`, `enigma/qa20.xml`). **No network was required to reach the export**;
the PDF is generated locally and written through SAF.

**The one rough edge — and it is a real one for this market.** The picker opens at the volume root,
which Android 11+ forbids, so the user's first screen reads:

> `Can't use this folder` / `To protect your privacy, choose another folder`

and `USE THIS FOLDER` is **greyed and disabled** (`enigma/17-export-done-offline.png`). Navigating into
**`Download` does not help** — Download is also blocked for `ACTION_OPEN_DOCUMENT_TREE` on Android 15,
and `USE THIS FOLDER` stays disabled (`enigma/qa23.xml`). Picking **`Documents` instead clears the
warning and enables the button** (`enigma/qa24.xml`: `USE THIS FOLDER … enabled= true`; the
`Can't use this folder` node is gone). `save-to-device.ts:57` calls
`requestDirectoryPermissionsAsync()` with no initial URI, which is why it lands on the forbidden root.

So: **the export works, but only if the user works out that `Download` and the root are dead ends.**
The obvious folder is refused with no explanation of which folder *will* work.

## 7. WHAT BLOCKED ME — the device left the USB bus twice, permanently the second time

The **Hisense Enigma dropped off `adb` twice**, and the second time it never came back. It was not the
app: the whole device disappeared from `adb devices`, and on the final attempts **both** phones
(Enigma *and* the Pixel 8 Pro) were gone from the list, which points at the host's USB, not the phone.

- **First drop** (~09:59): recovered after ~50 s of polling. A notification on the device read
  `USB debugging connected` / `Tap to turn off USB debugging`, i.e. the USB link was re-enumerating.
- **Second drop** (~10:05): never recovered. `adb kill-server` / `start-server` ×4 and ~10 minutes of
  polling produced an empty device list every time. Battery was at **20% · "Charging slowly"**.

**Consequences I am flagging explicitly:**
1. **Items 4, 5.5, 5.6 and 6 are unfinished** for this reason — not because they passed or failed.
2. **`screen_brightness` was NOT restored to 206.** The owner dimmed it to 12 for this run and asked
   for 206 back at the end. I got the device back once, used that window to restore the **radios**
   (proven, §1.5), and then lost it again before I could set the brightness. **The panel is still at
   `screen_brightness = 12`.** To finish it when the device returns:
   ```
   adb -s CTKS340F25102000240 shell settings put system screen_brightness 206
   adb -s CTKS340F25102000240 shell settings put system screen_brightness_mode 0
   ```
   `screen_brightness_mode` is already `0` and `screen_off_timeout` is already `60000` — both unchanged.
   `svc power stayon` was never set to `true` by me and `mStayOn=false` throughout, as asked.
3. The keyguard kept re-arming (`screen_off_timeout=60000`, `stayon=false`), and after the first drop
   `input keyevent 82` + `wm dismiss-keyguard` + a swipe-up **would not** clear it, so late taps landed
