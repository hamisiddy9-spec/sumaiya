§1The palette is fixed — what changes is which token does which job

Read verbatim from apps/web/tailwind.config.ts and apps/native/src/components/ui/theme.ts. 24 values, not one of them new. The only change is a usage rule, forced by measurement, not taste: --ember #DA4A1C measures 3.89:1 on cream and 4.22:1 on white — below WCAG AA 4.5:1 for 14px text. --ember-shadow #A8330F measures 6.16:1 and 6.68:1. So ember stays the fill and the icon; small ember text uses the darker existing token. Same family, same brand, legible.

Round the ad-hoc values

The tree carries gap: 9, gap: 11, gap: 2 and padding: 15 inline. Each rounds to the nearest allowed value — 8, 12, 4, 16. This is the single cheapest consistency win in the codebase: no layout changes, just one scale.

Density: 844px is the budget

Six quick-action tiles at 104px cost 336px — more than a whole job card and more than a third of the screen. At 60px each as an icon-well row they cost 196px, and the first job listing moves above the fold. Confirmed on the live device: the six tiles really do occupy about 875px of 2992 (≈29% of the screen). Nothing was removed; it was made shorter.

§4Corner treatment — one formula, not a mood

The app already applies this correctly in the icon wells (16 − 16 = 11-12 for a 38×38 well, 9 for a 30×30 well). It just needs to be the rule everywhere instead of a habit in some places.

RULE §4.1

inner radius = outer radius − outer padding

Clamp to the nearest token below. A card (16) with 16px padding holding a 38×38 element gets input-lg (12). A card-lg (20) with 20px padding gets card (16). Never hand-write 14 — it is neither an outer nor an inner token, and it is used today by ui/toast.tsx:133 and ui/list-row.tsx:54, and by profile-screen.tsx for a card-level container.

Weight and fill

strokeoutline, 1.75

Filled is reserved for (a) the active tab-bar icon, (b) the SumaiyaMark glyph. Everything else in this set is outline, and a filled icon visibly changes its weight.

Colour split (from §1)

Icons are non-text: WCAG asks 3:1 and ember passes. Text asks 4.5:1 and ember does not — which is why the two roles diverge. Stated as two rules so nobody has to remember the ratio.

ADDED §7.1 — Metric refresh

A match-score or ATS badge whose value changes while on screen updates its digits instantly (§4 already bans animating compared numbers) but its container may take dur.micro / ease.inOut on the background tint only. A fresh score no longer looks identical to a stale one, and the number the user is comparing never moves.

ADDED §7.2 — Banner stack

When more than one nudge renders above the fold (the web dashboard can render seven), they do not each animate. One Reveal on the group. Eight things arriving at once is noise pretending to be hierarchy.

ADDED §7.3 — Loading to content, enforced

Every ternary loading branch in the tree resolves to the standard’s “Loading to content” row: placeholder FadeOut 140ms ease.in while content enters at 300ms ease.out. A code-review checklist item, not new design.

ADDED §7.4 — The ban list

Banned outright: scroll parallax · backdrop-filter / blur transitions · spring-based list-item entrances (timing curves only) · any withRepeat without a 2-cycle bound and a cancelAnimation cleanup · more than about 100 simultaneously animated nodes.

STAYS INSTANT — do not add motion here

Typing · taps · scrolling · selection · numbers being compared · list text updating · keyboard avoidance

Apple-grade is not “everything moves”. Adding motion to any of these is a regression, and Reduce Motion collapses the rest to 1ms — never 0ms, so withTiming’s finished callback still fires.
