1

She introduces herself in the first person, once

The existing greeting (i18n.tsx:100) is already right: “Habari, mimi ni Sumaiya…”. It keeps the one place where a person-ness is earned. Everything else on this screen is chrome and stays second-person or names the outcome.

2

“Tengeneza CV yangu” → “Tengeneza CV yako”

A control the product renders is chrome, not something the user said. The audit found this card first-person (chat-types.ts:132) beside a first-person-feature label elsewhere in the app. copy change, not a behaviour change

3

“Ongea nami” stays exactly as it is

That one is her speaking about herself (an invitation), which the Swahili voice rule permits. It is quoted here so nobody “fixes” it into a feature label.

4

Four cards, 60 dp tall, one decision

Tapping one seeds the conversation — unchanged behaviour, and the reason the empty state is not a blank field. The brief strip in the app keeps 2-up at every font scale; at 200% text the grid becomes one column, never clipped.

5

A system note that answers a real question

The transcript already survives a process death (use-sumaiya-chat.ts:50-75) and nothing ever said so. This line says it in one short sentence. a vision reviewer called this the one thing to cut on this screen It is the first thing to remove if the empty state should be quieter — it is the lowest-value element here, and the same component carries the higher-value notes (“nimerudisha ombi lako”, “mazungumzo yamefutwa”, retry receipts) elsewhere.

6

The composer, made honest

+ and send are 44 dp (the audit measured 40). The field grows to 5 lines then scrolls, and Enter never sends (chat-composer.tsx:148 — keep that). A disabled send is sand with a muted glyph and the placeholder says why it is disabled; it never becomes an invisible tap target.

7

Nothing on this screen pops

Greeting rises first, the four cards stagger 30/70/110/150 ms (cap 6, MAX_STAGGER_MS 270), the note lands last. All of it is transform+opacity, all of it interruptible, all of it instant under Reduce Motion.

What this screen replaces

Nothing new is added. The greeting, the four cards, the +, the field and the send button all already exist. What changes is the wording of one card, the size of two touch targets, one new line of text about persistence, and the arrival order.

The prototype loop that plays these entrances is the same one a developer can read: rise 300ms ease-out (0.33,1,0.68,1), stagger 30 + min(i,6)×40.
