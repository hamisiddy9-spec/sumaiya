The chatbox, redesigned — five screens.

“Feel free to redesign everything — animations, chatbox and its features.” This is that, as five screens a developer can build from, plus the audit and the research behind them. No source file was changed. Palette and logo untouched; every colour below is read out of tailwind.config.ts and theme.ts, and every duration out of the motion standard.

Fungua

What every screen obeys

  • Nothing appears. Everything arrives — 300 ms ease-out in, 140 ms ease-in out, no frame where the surface is blank.
  • Everything is interruptible. A stop control exists from the first second of every wait; a tap supersedes an in-flight animation rather than queueing behind it.
  • Reduced motion is respected, never removed. Every duration collapses to 1 ms; every state stays legible as static text.
  • Cheap to render. transform and opacity only (except the one sanctioned reflow), no unbounded loops, stagger capped at 3 items in a chat run.
  • No colour invented, no logo touched. The mark in every mockup is the real three-blade geometry from logo.tsx.

The four ideas that carry the redesign

  • Waiting is reported, not decorated. Real steps, past tense when finished, a bar that counts finished steps.
  • Work leaves the chat and can come back. A document card that passes identity into the editor and returns in its saved state — not a copy with no id.
  • The user's words are sacred. Never cleared, never re-typed, resendable as the same turn.
  • Unavailable is a planned state, not an error page. First person, never begging, never a dead end, and never a fake success — designed for the day a provider fails, not because one has.
