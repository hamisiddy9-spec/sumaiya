What the product says tonight — quoted from the live build

"AI is not configured."

English, inside a Swahili screen, in Sumaiya's own bubble. This is the raw JSON body of an 18-site 503 (apps/web/lib/api/routes/ai.ts:157 and 17 siblings), rendered as if she had said it. Captured live: QA-WEB-JOURNEYS-2026-09-20.md §D3.

"Sumaiya ana shughuli nyingi sasa hivi. Jaribu tena baada ya muda mfupi."

Third person — the app describing her rather than her speaking — shipped in the bundle after the first-person fix (QA-NATIVE-DEVICE-2026-09-20.md §4b). It also blames her workload for a provider that is simply switched off.

"Boresha na AI" → 200, input returned unchanged, {"source":"local"}

A button that names AI, reports success, and changes nothing. The editor already knows how to be honest about this (cv-editor-client.tsx:2774-2777); the chat does not.

"Hifadhi kwenye akaunti yako" — rendered disabled, no tooltip

The snap-to-apply dead end: the user is asked to want something the screen will not let them have, and is told nothing.

The rules this state obeys

1. She speaks about herself in the first person, always. Sina uwezo… · Sikuweza… · Nitakujibu nikirudi. Never her name in the third person from inside her own bubble (the Swahili standard's two-speaker rule, SWAHILI-STANDARD-2026-09-20.md §4.1, applied to the transcript).

2. Never beg, never blame. No “please try later”, no apology loop. The reason is named, and the one thing that is not the cause is ruled out explicitly — because the app has a history of blaming the user's connection for our own faults (app-errors.ts:200-204).

3. Never dead-end. Every state carries at least one control that genuinely works right now. A control may only be disabled with its reason printed beside it.

4. Never fake success. If the work was local, the artifact says so, on the artifact. Silently returning the input under an AI label is the one failure a user cannot forgive.

5. The user's words are sacred. They are never cleared, never require retyping, and “Jaribu tena” resends the same turn rather than asking for it again.

6. It is a state, not a page. It arrives as a system card inside the thread (rise 300ms ease-out), it replaces the progress rail rather than being pasted over it, and it disappears by itself when it clears — with no toast to dismiss and no red.

1

Detection is a probe, not a guess

GET /api/ai/status already returns {configured, provider} (routes/ai.ts:113). Screen A uses it on entry; screens B and C use the turn's own outcome. No connectivity heuristic, no “offline” cache-only logic — the app asks the thing that knows.

2

What still works is not marketing — it is a list of endpoints that do not call a model

ATS scoring and the keyword diff are deterministic; PDF export is local; OCR runs on tesseract; the job feed is a database read. Those are the three rows offered. Nothing is offered that would fail.

3

“KWA SEHEMU” is a header badge, not a warning colour

Gold (#F2A93B / #96630F) exists in the palette for exactly this: degraded, not broken. The error red is reserved for a real fault, so the two never mean the same thing on screen.

4

The card retires itself

When the probe succeeds, the card exits at 140ms ease-in while the normal composer state enters at 220ms ease-out — the standard's “Loading → content” hand-off, in reverse. No confetti, no “AI is back!” toast.

5

Reduced motion keeps every word

Nothing on these three screens is motion-only: the heading, the reason, the working list and the disabled-thing line are all static text. At dur.instant the state is still complete and still honest.

7

If this card has to shrink, the heading is the last thing to go

A vision reviewer proposed cutting the “Sina uwezo wa kufikiri sasa hivi.” block because the three working actions below already imply it. That inverts the priority: the sentence is the state; the list is the consolation. The order to cut is (1) the ruled-out line, (2) the sub-lines under each working action, (3) the footer sentence — never the heading, and never a control.

6

One owner decision is avoided, not hidden

If the 503 arrives because of an owner-side quota rather than a missing key, the same card shows the same first sentence and a different second one (“Nimefikia kikomo cha matumizi ya leo.”). The chat never has to know which, and the user never sees a status code.
