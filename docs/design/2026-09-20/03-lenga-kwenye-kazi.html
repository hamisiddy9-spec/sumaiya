03 — “Lenga kwenye kazi”: chagua yetu, au yako

The owner's own requirement — “iwe na option ya kuchagua kazi ya user yani atoe source au achague zetu” — already exists in the code (job-choice-sheet.tsx, job-choice-panel.tsx) and is already good. It is simply impossible to find: it opens only if a keyword match happens to place a chip. The redesign makes it a door you can always walk through, gives it the entrance animation the motion standard already specifies for a sheet, and shows what happens on both paths.

Niandikie…
1

One always-available door

Today this sheet only opens from a chip that a keyword test has to earn (use-sumaiya-chat.ts:250-252: kazi, ajira, tangazo, lenga). The composer's + menu gets a fifth row — “Lenga kwenye kazi” — so the capability exists whether or not the conversation happens to contain the right word. It replaces nothing; it reveals what was already built.

2

Two paths, side by side, at thumb height

Both path cards sit in the bottom half of the screen, 56 dp tall, and the second path says what it accepts (“Bandika tangazo, au kiungo chake”) before it is chosen — a link that is not read is not a link. Copy is the live app's, verbatim.

3

The search says what it is doing

Inatafuta… with the 350 ms debounce already in the code. The empty branch stays honest: “Hakuna kazi inayolingana na “mauzo”. Jaribu neno lingine, au weka kazi yako mwenyewe” — the second clause matters more than the first.

4

A listing with no advert says so, and the offer stays open

The live sheet already refuses to run the engine on a title alone (job-choice-sheet.tsx:167-171). That is the honest behaviour and it is kept: “Tangazo hili halina maelezo ya kutosha. Bandika maandishi yenyewe.” — and the second path is right there under it.

5

The sheet arrives like a sheet, not like a screenshot

Backdrop fades 220ms ease-out, panel rises translateY 360→0, 220ms ease-out; leaving is 140ms ease-in. Both are already written into the motion standard (§3.5, “Sheet (bottom)”) — they are simply not implemented (job-choice-sheet.tsx:156 returns null with no exit). Reduced motion: cross-fade only.

6

Choosing our listing loads one advert, on purpose

Opening the sheet: zero requests. Opening “ours”: one ?light=1 call for titles and companies. Choosing a row: one call for that advert. Typing: debounced. Nothing else. The sheet's own comment (job-choice-sheet.tsx:25-26) already measures this; the redesign keeps it and says it in the UI so a user on metered data understands why the list is thin.

7

“Lenga ajira hii” never dead-ends again

On the live build the equivalent control did not fire at all, and its sibling dead-ends on a disabled save (QA-NATIVE-DEVICE §4d, QA-WEB-JOURNEYS §D1). The rule the redesign imposes: the primary control's label names the outcome, it is never disabled without a stated reason, and the line under it promises exactly what happens next (“Nitaonyesha kila nilichobadilisha kabla ya kuhifadhi”).

What this replaces

Nothing is removed. The sheet, both paths, the debounced search, the 12-row projection and the empty/error/notice branches are all already built. This screen adds one entry row in the + menu, unifies the chip label (native says Lenga kwenye kazi, web says Lenga CV kwa kazi — same action, two names), and gives the sheet the entrance the standard already specifies.

Deliberate non-change: the two path labels keep their current first-example wording because a native speaker wrote them and the owner approved the phrasing.
