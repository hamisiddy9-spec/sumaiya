Lugha moja ya madirisha (one overlay language)

The popups are a zoo: three native sheet radii for the same object, six web scrims and seven z-indices where the theme already defines one scrim. This is one system, five variants, and an audit of every real overlay by file:line.

Colours and the logo are FIXED — read from apps/web/tailwind.config.ts and apps/native/src/components/ui/theme.ts. Motion obeys docs/MOTION-STANDARD-2026-09-20.md. No source file is modified by this proposal.

AFive variants, and only five

Every overlay in both apps maps to one of these. If a new need appears that does not fit one of the five, the answer is the nearest variant, not a sixth shape.

spring configs on overlays3 (18, 20, and 20/240)

Why this is worth fixing now

Every one of these overlays is a moment where the user is being asked something or told something important — a destructive confirm, a share, a paywall. Those are exactly the moments the app must read as one object rather than as a collection of one-off components. The fix is small and mechanical: one scrim constant, one z-ladder, three radii, five variants. No new dependency, no new screen, and the web and the APK become recognisably the same product at the moment the user is deciding something.
